# Shared API contract
All routes authenticated under authHook. Responses JSON; `{error: string, code?: string}` on failure. Mutations reject demo non-admin; source listing checked with userCanAccessListing then state private to currentUser (admin cannot read another user's profile/workflow). Finite request sizes and string limits, epoch dates represented ISO8601 UTC strings in JSON. Root wires routes. No secret values in GET responses/errors/logs.

## Fit (/api/fit)
GET /profile => {profile: {document: string, criteria: Criterion[], version: number}, provider: {configured: boolean, model: string}}
POST /profile {document, criteria} => same profile envelope. document max 32KB, <=30 criteria. Criterion {id, text, required:boolean, weight:number(1..10), kind:'semantic'|'min_rooms'|'min_size'|'max_price'|'station_line', value?:number, line?:string, maxWalkMinutes?:number}. id server validated/normalized; text single natural language requirement. Plain-text/Markdown document input (no PDF/OCR claim); editable line-derived criteria in UI. Bedrooms/kitchen/furnishing/lease are semantic, rooms numeric distinct.
GET /listings/:listingId => {result: FitResult|null, stale:boolean}
POST /listings/:listingId/evaluate {} => {result:FitResult,stale:false}. 503 code not_configured/provider_unavailable; existing results remain visible but no fabricated success.
FitResult {score:number(0..100), coverage:number(0..100), hardFailure:boolean, hardUnknown:boolean, criteria:[{id,text,required,weight,verdict:'met'|'unmet'|'unknown',confidence:number,evidence:[{source:string,text:string}]}],profileVersion:number,evidenceHash:string,evaluatedAt:string,model:string}. Unknown contributes zero to conservative score, coverage explicit. Score never overwrites hard failure/unknown. Provider model served id recorded; malformed answers rejected; evidence text from actual source, no invented model narrative. Stored result stale if profile/listing/evidence changed; never cache outages as successful fit.
Station_line performs bounded line-aware station lookup around real listing coords, using fixed Overpass endpoint plus existing walking routing to candidate station(s). Unknown on genuine missing/provider data; no claiming nearest generic station is a U2 station. Exact walking unavailable => unknown, optional straight-line lower bound shown only as evidence. Lookup cached, throttled, finite geographic/request/body/time limits; line restricted to safe literal length/chars.

## Applications (/api/applications)
GET / => {applications: Application[]} current user's accessible source listings only; includes title/link for display. GET /listings/:listingId => {application:Application|null,events:Event[]}.
POST /listings/:listingId {status?,recipient?,subject?,body?,visitAt?,followUpAt?,autoSendAt?} => {application,events}. New record default draft. Application {id,listingId,title?,link?,status,recipient,subject,body,visitAt:string|null,followUpAt:string|null,autoSendAt:string|null,sendState:string,updatedAt:string}. Status draft|submitted|replied|visit_scheduled|follow_up|rejected|accepted|withdrawn. Manually recorded submitted is labeled manual, distinct SMTP send receipts. Empty dates clear; valid ISO strings; max message body 32KB.
POST /listings/:listingId/events {kind:'note'|'reply'|'visit'|'follow_up',text:string} => {application,events}. Manual reply updates replied; timeline records actor/source. No forged automatic send receipts through event API.
POST /listings/:listingId/send {idempotencyKey:string} => {application,events}. Sends current persisted reviewed draft only. Valid explicit recipient, configured SMTP, claims atomic reservation; repeated same key replay outcome. Ambiguous delivery => unknown/manual review, never automatic retry. Queue: opt-in autoSendAt with fixed recipient/subject/body, visible in UI; changes/cancel invalidate pending dispatch. Auto jobs only claim once and recheck current listing ownership/access.
GET /listings/:listingId/visit.ics => text/calendar (user authenticated; escaped text, UTC time; no arbitrary headers).
GET /mail => {smtp:{host,port,secure,user,from,configured,passwordSet},imap:{host,port,user,mailbox,configured,passwordSet},lastSyncAt?:string,lastSyncError?:string} no secrets.
POST /mail {smtp?:{host,port,secure,user,from,password?},imap?:{host,port,user,mailbox,password?}} => sanitized config envelope. Password omitted retains; null clears. User-owned config encrypted using persistent /conf master key mode0600; atomic creation and strict no fallback on corrupt key.
POST /mail/sync {} => {matched:number,scanned:number}. Automatic same sync every 5min with per-user locks. IMAP only verified TLS/STARTTLS; no secret/protocol logger; bounded fetch/body parsing; UIDVALIDITY+UID cursor and dedup. Exact In-Reply-To/References of recorded outbound Message-ID scoped user, never subject/sender heuristic; no cross-application linkage ambiguity. Inbox headers/content displayed as plain text.
GET /setup (optional) => capability/setup info if needed. Scheduler export startApplicationScheduler() invoked once by root after migrations; returns stop function/timers unref. No production real sends during tests; fake SMTP/IMAP exercised.

## UI ownership
UI worker owns all frontend additions/wiring and translations. Use separate SearchProfilePage and ApplicationsPage, FitCard and ApplicationTracker on listing. Original application copy modal records draft or leaves workflow unchanged, never marks submitted/applied merely copying. Reuse existing /api/listings/:id/application response {text,...} to draft. Show missing provider setup; scheduled send opt-in explicit, response receipt vs queued clearly distinct. Existing listing notes remain unchanged.

## Deployment/review resolutions
PR-01: this is the shared contract. Workers must message deviations BEFORE implementing caller changes.
PR-02: build/check while current app runs; stop current app and wait no old writer; snapshot both volumes via backup container while stopped; SQLite integrity verification of database snapshot. Replacement migrates while old stopped. On failed deploy stop new writer, restore DB+conf snapshot with all writers stopped, restart old exact image/config, verify healthy. Backup before migration contains original data; no WAL-unsafe copies of live files.
PR-03: require real bounded station_line implementation; unknown reserved for missing/outage evidence, not missing feature.
PR-04: auto deployment polls and deploys each unseen first-parent main commit in order (git rev-list --first-parent --reverse deployed..origin/main), with durable per-SHA result. Reject non-fast-forward main without rewriting state. Retry only failed build/deploy after next poll with log; no duplicate successful deploy. Thus every commit introduced by a main push gets checked/deployed, rather than silently coalescing pushes. Bootstrap starts at current main/deployed revision. Path supports merge main history. Exact push-event identity unavailable without webhook, so state honestly records commit-triggered polling.
PR-02 final activation invariant: new deployment starts with FREDY_DEPLOYMENT_GATED=1. Root runtime module rejects state-changing API requests (except login/logout session plumbing) until a container-local activation marker exists. index.js waits before initializing any existing/background scheduler; application/mail scheduler also checks activation dynamically. Migrated replacement accepts read-only verification while paused; poller releases only after preactivation checks. Snapshot restore is allowed only before activation. After activation any rollback is image/code-only and retains the migrated DB and all subsequent writes/outbox receipts. Migrations additive, previous image ignores new tables. No unattended postactivation snapshot restoration.
Integration amendment: Application additionally returns revision:number. Manual /send requires expectedRevision matching the draft the user reviewed, checked atomically with the reservation (prevents cross-tab replacement race); scheduler supplies its claimed revision internally. /resolve-delivery {outcome:'sent'|'not_sent',note:string} is an explicit mailbox reconciliation action for uncertain reservations; it must preserve the historic send receipt and cannot cause an automatic retry.
